# Prepared 方差全链路精度排查

本轮只核查源码并增加 CPU 审计脚本与结果，未修改运行 shader、设置或提交。目标是区分存储/运算精度与统计模型、输入历史不同导致的空域/时域方差差异。

## 源码检查

| 阶段 | 当前契约 | 核查结果 |
| --- | --- | --- |
| PT diffuse 输出 | 直接与间接方向包先相加，RMS 为该次总亮度的绝对值 | 没有在输入时把平方值当成 RMS；该输入可能是多方向组合包 |
| PT reflection 输出 | 入射与直接方向包相加，单次总亮度用于后续二阶矩 | 存在 radiance clamp，需与量化区分 |
| diffuse 历史/重投影 scratch | 末尾两半精度字段为 `(N_eff,RMS)` | temporal pack/unpack、variance adapter、shared tile 顺序相符 |
| reflection 历史/重投影 scratch | 末尾两半精度字段为 `(RMS,N_eff)` | temporal、history staging、variance adapter 顺序相符 |
| 重投影 | 均值与 RMS² 按相同线性权重混合，之后开平方打包 | 未发现 RMS 被直接线性平均；重投影的 p=1 Kish 属于相关性模型 |
| 时间 proposal | 均值与二阶矩均使用 alpha=0.01，计数独立更新 | proposal 和最终 resolve 具有不同权重，审计需区分两者 |
| 空间方差 | 7×7 混合均值、RMS²；`N_pool=W²/sum(w²/N)` | 调用与时域相同的方差函数，Prepared 阶段未额外除以 N |
| 时域方差 | 中心 proposal 的均值、RMS、N | 与空域输入来源不同，函数和观察方差口径一致 |
| Prepared 输出 | 混合两种观察方差，存 `sqrt(V)` | `N_eff` 控制 smoothstep；配置值不是实际 elapsed frames |
| Debug 输出 | 接收标准差，平方后显示 `log2(1+V)/16` | 两种来源共用固定尺度，没有逐图自动归一化 |

这是静态读写路径检查，没有捕获 Minecraft 实际 dispatch、GPU 内存、运动几何或分支选择。没有据此声称排除了运行时资源绑定和同步问题。

## 可复现数值检查

```text
python -B tools/audit_variance_precision.py
```

结果为 `calibration/variance_precision.json`，记录种子 906202613、Python/NumPy 版本、源码哈希、逐检查点结果和 100 组输入矩精度扫描。

脚本对照 FP64、FP32、带相同存储范围 clamp 的 FP32、FP16 存储、FP16+假设 FTZ。FTZ 是压力测试，不表示当前驱动确实清零半精度次正规数。

时间测试使用 48×48 均匀平面、共同原始随机流、固定 alpha=0.01、初始 N=32，运行 512 帧。分别模拟原始打包、重投影、proposal 打包、独立 scratch 打包、commit 写回、shared tile、7×7 pooling、Prepared 混合与 debug 标量映射。支持恒等重投影及固定 `(0.4,0.3,0.2,0.1)` 双线性重投影；后者使用周期边界。

为隔离精度，固定所有采样、历史和几何选择；没有复现自适应时间响应、A-Trous、PT/NEE/ReSTIR 或真实 GPU 的 FMA 与 flush 行为。输入光照采用对数正态亮度和固定极角随机方位方向，明确不假定它是 g^-3 联合随机变量。本轮比较的是同一公式在不同精度下的数值结果。

## 结果

正常条件：平均亮度 256、亮度变异系数 1、方向平均集中度 0.7，无亚像素重投影。

| 精度 | 时域方差均值 | 空域方差均值 |
| --- | ---: | ---: |
| FP64 | 118.195062 | 119.822373 |
| FP32 | 118.195004 | 119.822311 |
| FP16 存储 | 118.197197 | 119.817335 |

该例 FP32 时域方差相对误差 P99 为 2.48e-6；FP16 为 1.37%。未复现倍数级的系统性时域低估。

低方差、单方向条件：平均亮度 256、变异系数 0.01、集中度 1。

| 精度 | 时域方差均值 | 空域方差均值 | 时域零值比例 |
| --- | ---: | ---: | ---: |
| FP64 | 0.00639409 | 0.00639473 | 0 |
| FP32 | 0.00630452 | 0.00629718 | 0 |
| FP16 存储 | 0.01290995 | 0.00866972 | 67.32% |

FP16 中大量零值与少量较大值并存；误差方向并不固定。这说明精度问题存在，也说明它不能直接等同于“时域总是低于空域”。亚像素重投影会进一步改变误差：此低方差例的 FP32 时域均值降至 0.00582328，而 FP64 为 0.00642548，反复重建后的相对误差 P99 为 10.31%。

其他核查：

- 10000 组半精度字段位打包/解包通过，未发现 N 与 RMS 槽位互换。
- N=32 附近可表示的相邻半精度值为 31.984375、32、32.03125。`1/(1-1/N)` 分别约为 1.032274、1.032258、1.032226，不存在倍数级修正跳变。
- 固定 alpha=0.01 的长历史：FP64 计数趋近 199；FP16 计数在本例停在 195.875。观察方差的有限样本修正差异很小，但不能把量化后的计数视为精确权重平方和。
- 极低亮度的半精度次正规数敏感性明确存在。假设 FTZ 时，测试信号会整体归零；实际驱动行为尚未测量。
- HDR 压力测试中，存储范围 clamp 本身就使方差明显降低；带 clamp 的 FP32 结果与 FP16 接近。这类偏差需归类为饱和裁剪，不应归咎于尾数精度。
- Display 的 `log2(1+V)` 在极小 V 下也会丢失精度，但只影响可视化，不回馈方差准备或滤波。

## 结论与未完成项

现有检查没有发现函数错用、N/RMS 字段互换、Prepared 的额外 N 除法或显示自动缩放。常规局部同分布条件下，算术和存储精度没有复现观察到的大范围时域低估。

仍不能全面排除精度：小中心方差、接近单方向的角向差、反复重投影、次正规数和饱和均是实测敏感区。必须知道实景输入落在哪个区间，才能判断这些问题是否解释截图。

后续实景审计需要同一帧、同一组原始输入及权重的阶段快照，至少包含中心/邻域 `v,w,RMS,N_eff`、实际 temporal alpha 和重投影权重。只对最终已量化矩换 FP64 计算，无法排除更早的历史量化损失；比较修改参数后分别生成的两段历史，也无法隔离精度和响应反馈。
