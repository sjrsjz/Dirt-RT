# 游戏性能反馈后的联合诊断：捕获 10 / 11

用户在上一轮修改后报告游戏内性能倒退，并提供 `temp/analysis_11.yaml`。上一轮独立内核微基准不足以判断游戏收益：它没有完整覆盖真实输入、连续 pass 的缓存状态、图像生命周期、宿主同步和频率变化。即使独立内核计时下降、数值验证通过，也不能据此认定整帧已优化。本文先记录两次捕获的联合证据与待验证假设，避免将推测写成根因。

## 数据范围与时间口径

对照 `temp/analysis_10.yaml` / `temp/analysis_11.yaml` 的全部 Rules：分别有 1,100 / 1,127 条规则、3,066 / 3,147 个指标出现位置，合计 113 种指标名。原始规则、逐指标差值与逐 pass 汇总保存在 `temp/bench11/profile/`；没有只选 Overview 的前五项。

两份 `composite` 都是编号子范围的聚合：帧份额之和相等，GR 周期之和与父范围均只差 27 周期。两个 `prepare` 在各自捕获中完全重复。去重并排除父范围后，叶范围只覆盖整帧的 47.4186% / 48.5230%；剩余时间不能全部归给 PT。

导出文件没有绝对帧时、pass 毫秒和频率轨迹。某 pass 份额为 p、整帧时间为 F，则 `T11/T10 = (p11/p10) × (F11/F10)`。份额上升不直接等于绝对耗时上升，GR 周期也不能在未知频率下换算毫秒。`FrameGain` / `RangeSpeedupFactor` 是诊断模型预测，未作为实测收益使用。

### 第一优先假设：scratch 迁移的完整成本

前五级仍传播两个估计器，没有末级 proposal 裁剪，因此主要暴露统一 scratch 迁移本身的代价与收益。入口是 [scratch_io.glsl](../shaders/lib/lighting/denoiser/scratch_io.glsl)、[atrous_small.glsl](../shaders/lib/lighting/denoiser/atrous_small.glsl) 与 [atrous_filter.glsl](../shaders/lib/lighting/denoiser/atrous_filter.glsl)。

| 联合信号 | 捕获变化 | 能支持的判断与限制 |
| --- | --- | --- |
| 访问路径 | 小核 TLD sector 份额约 81–82% → 94.6%，global-load 约 15–16% → 2.34%；大核也明显转向 TLD | 负载从 SSBO 迁向图像读取；流量份额不是绝对字节，旧 LSU 与新 TEX 吞吐不能直接视为同一指标 |
| 整数工作与算术调度 | 图像编解码每次对四个字加/减偏置；多数小核 ALU 约 48–50% → 65%，math-pipe throttle 约 2.8–3.4% → 3.9–5.4% | 整数处理、活跃值及调度成本需要检查；单个 ALU 百分比不能证明新增指令数或运行时间 |
| 缓存与等待 | 小核 L1 命中提高约 2.6–3.3 个百分点，long scoreboard 普遍下降；short scoreboard 从约 1.40–1.65% 变为 1.56–2.10%，并非每级都增加 | 访问收益与算术代价同时存在，不能只依据缓存改善认可迁移；短依赖变化也不支持所有阶段同一原因 |
| 发射与寄存器 | 新小核 register-allocation launch stall 约 39–49%；聚合 composite 为 3.3802% → 20.1962% | 旧小核该项未导出，不能写成 0，也不能据此断言寄存器数增加；需读取 NVIDIA 实际编译资源 |
| 52 的异常 | 新 SM 指令吞吐约 62.6%，其他小核约 81.4–81.6%；occupancy 也单独下降 | 应保留该样本及其上下游，不能用两域平均抹去异常 |

**51/52 的位置差异是必须解释的反证。** 同样的 scratch 算法下，它们的 GR 周期增加 5.76% / 2.39%，而 53、66–68 减少约 5–7%。所以“整数偏置单独导致所有前五级变慢”不成立。51/52 位于漫反射开始使用两张复用图像的位置；先前辉光的读写状态、下一帧首次写入/读取、驻留、缓存及宿主屏障可能与后续阶段不同。这是待测的生命周期假设，YAML 没有证明布局转换或屏障就是根因。

最有区分力的对照是保持算法与生命周期裁剪一致，比较原 SSBO scratch、当前辉光图像复用、相同编解码的独占图像。需要包含“前帧辉光 → 方差准备 → 连续空间阶段”，而非只重复运行热缓存中的单个核。独占图像若消除退化，支持资源复用相关成本；若没有，再检查整数处理与实际机器码资源。对照应同时适用于两个域。

### 第二优先假设：大核并发下降抵消访问收益

[atrous_large.glsl](../shaders/lib/lighting/denoiser/atrous_large.glsl) 对应的 54/55/69/70 occupancy 从约 32.2–32.5% 一致降到 28.3–28.4%，平均活跃 warp 约从 15.4–15.6 降到 13.6。L2 吞吐增加约 3.9–4.9 个百分点，而 L2 命中仍约 94–96%。这组跨两域、两步长重复出现的变化，比单项 top-rule 排名更值得检查。

它尚不构成显存或 TEX 饱和的证据：有导出值的 55/69/70 VRAM 吞吐仅约 21–23%，新大核 TEX throttle 约 0.0009–0.0013%。long scoreboard 下降但周期只改善约 1–1.5%，符合访问改善与并发下降相互抵消的表现；具体资源原因仍待确认。

shared-memory-allocation launch stall 大致保持 44–49%，也出现在没有 GLSL shared 数组的小核。各类 launch stall 可以重叠，不能相加，也不能直接等同于显式共享内存容量不足。RGA 的 gfx1100 VGPR、LDS 和 ISA 仅描述 AMD 编译结果，不能代替 RTX 4060 Laptop 上的 NVIDIA 寄存器分配、指令调度或 occupancy。

聚合 composite 的 CS/PS 线程数保持不变，但 draw 由 63 增至 108；部分 CS 范围有 draw 计数而 PS threads 为 0。这些异常应保留并用事件时间线定位，不能凭计数认定发生了图像格式转换。缺失指标也不能按零补齐；long/short scoreboard、管线吞吐和累计 warp 延迟各有统计口径，不能拼成互斥时间总和。

## 后续验证方法的约束

新的[空间串联基准](../tools/benchmark_spatial_chain.py) 使用真实生产入口和五级估计器交替传递，一个 query 覆盖连续 dispatch，输入恢复在 query 外进行。它仍使用合成场景，不能替代游戏整帧和跨帧辉光资源交接测试。

候选筛选已经提供一个直接反例：`compact_metadata` 单独使五级链的配对耗时下降约 7.14%，`trusted_weights` 单独下降约 8.18%，两者直接合并为 `trusted_compact` 却令耗时**增加约 49.24%**；三者在该样本的末端输出均逐位一致。原始样本位于 `temp/bench11/screen_compact.json` 与 `screen_coherent.json`。百分比使用 `1 - 1 / median(T基线/T候选)`，所以合并版本是耗时增加约 49%，不是速度比降低 49%。

单项收益不能相加，数学等价与正确输出也不能保证优化组合更快。编译后的活跃范围、共享数据使用和调度可能相互作用；这一反例目前只证明必须实测组合，具体修复与因果证据应另行记录。所有候选应保持统一架构，并同时检查正确性、单项/组合对照、连续阶段计时及实际游戏表现。

可用[捕获解析工具](../tools/analyze_gpu_profile.py)重建单次捕获摘要：

```powershell
python tools/analyze_gpu_profile.py temp/analysis_11.yaml --output temp/bench11/profile_11.json
```

本次完整对照由 `temp/bench11/profile/compare_profiles.py` 生成，保留 `comparison_all_rules.json`、`all_metrics.csv` 和 `pass_summary.csv`。它们提供所有规则和原始范围顺序；本文仅压缩呈现与联合判断有关的证据。

## 已落地的统一实现

本轮基线为 `temp/bench11/baseline_shaders`，是本轮开始时的源码快照，已经包含上一轮图像 scratch、末级 proposal 和诊断写入裁剪。YAML 没有源码摘要，无法独立核实捕获时的版本。本轮实际修改七个共用模块，两个信号域仍使用相同算法、工作组和六级调度：

| 模块 | 本轮变化 | 保留的契约 |
| --- | --- | --- |
| `atrous_filter.glsl` | proposal/current 按消费者保留不同累加字段；空间方差累计复用均值的总权重，移除封闭链内重复的通用输入检查 | 相同 tap 权重、独立的估计量 sigma、未知方差的平方权重与既有重叠相关闭合 |
| `signal.glsl` | 增加只供已清理空间链使用的 FP16 有效性判据，并明确角色 ABI | 通用 16 字节布局；history/reprojection/resolve 继续使用完整检查 |
| `atrous_small.glsl` | 两位偏移常量和对角线掩码替代动态索引数组；接入 current 专用累加器 | 八个邻居的位置、顺序与原始 FP32 权重字面量不变 |
| `atrous_large.glsl` | 接入 current 累加器及空间快捷检查 | Poisson 采样、旋转、虚拟平面与共享瓦片不变 |
| `atrous_tap.glsl`、`geometry.glsl` | 对准备后的邻居及虚拟位置采用同一快捷判据 | 两个估计器共同有效性判断和独立几何检查仍保留 |
| `variance_prepare.glsl` | 从空间链入口就清零 proposal 色度及 current 虚拟距离 | 原始矩、方差准备、持久历史及唯一提交点不变 |

proposal 在空间链中只需要 `maxEntY / sigma / virtualDistance`，其 `CoCg=0`；current 只需要 `maxEntY / CoCg / sigma`，其 `virtualDistance=0`。它们从 50/65 开始满足该约束，末级仍只发布 current。通用信号依然占 16 字节；这里减少的是解码、累加及活跃字段，没有再次缩小存储 ABI。详细职责见[架构文档](shader_architecture.md)和[降噪阶段表](../shaders/post/denoiser/README.md)。

快捷检查的前提是方差准备清理输入、每级空间 resolve 清理输出，sigma 只能为有限非负数、-1 或 -2。比较低半字是否为 FP16 的 -1，可省掉空间邻域内重复解码与有限性判断；它不能用于任意外部编码。未知方差仍贡献自己的平方权重并仅借用已知 sigma，没有变成零噪声。

## 候选取舍与 NVIDIA 编译证据

源码更短、静态指令更少不足以决定取舍。直接合并 `trusted_weights` 与 `compact_metadata` 的筛选退化已在前文保留；驱动中间表示却同时减少了指令和分支，并没有循环展开增加的证据。需要改变具体编译输入并重新对照，而不是据此虚构最终后端根因。

| 候选 | 可核查证据 | 取舍 |
| --- | --- | --- |
| 直接合并 `trusted_compact` | 五级筛选耗时增加约 49.24%，但输出逐位相等、NVcp 中间代码更短 | 不直接采用该组合；先减少无消费者字段的活跃范围 |
| 显式展开八个 tap | 消除了动态局部表；51/54 的 NVcp 中间代码约 30/28 KB 增至 74/73 KB，虚拟临时变量也增加 | 与角色裁剪版本直接比较的收益接近零，不采用代码膨胀的方案 |
| `table_bits` 加角色裁剪 | 保留循环，用三次 `BFE.U` 取偏移与权重选择位；小核动态局部表消失，中间代码从 30,066 降至 29,633 字节，`R0..R20` 不变 | 采用，并将角色清零提前到方差准备；用下文完整空间串联结果验证组合 |

`table_bits/cpu_proof.json` 穷举八个 tap，确认坐标、顺序及两个权重的 FP32 位模式完全相同。常量为 `0x9224`、`0xa940` 和 `0xa5`，保留 `0.44445 / 0.66667`，没有用理想分数替代已舍入的系数。

其余筛选也保留在 `temp/bench11/screen_*.json`：并行发出邻域读取虽改变了 AMD 的等待序列，在 NVIDIA 连续链上未表现出稳定增益；取消方差 known/unknown 分支增加了每 tap 算术；视空间替换及归一化距离折叠出现了额外数值差异。这些候选均未合入生产代码。

NVIDIA 证据来自驱动导出的 `!!NVcp5.0` 中间汇编，不是最终 SASS。其中 `R` 是虚拟向量寄存器，`lmem0` 是中间局部数组，不能据此称为实测 spill。重新编译该汇编后的 ARB native 查询也不等同于原始 GLSL 的最终资源分配；compact 与 combined 的 native temporaries 相同，仍不能解释运行时间差异。没有从程序二进制中取得有效 ELF，因此未将猜测偏移交给 `nvdisasm`。完整记录见 `temp/bench11/pipeline_cost/NVIDIA_COMPILER.md`。

这组证据支持“移除了驱动实际生成的动态局部表”，尚未证明游戏中最终物理寄存器或 occupancy 改善多少，也未单独证实前述图像生命周期假设。

| 72 | 54 → 54 | 46 → 46 | 0 → 0 | 8,828 → 8,828 | 21 → 21 | 1 → 1 | 34 → 34 |

所有条目 `SCRATCH_MEM=0`。大核 SGPR 有上升，不能写成所有资源都减少。部分纹理加载的分量掩码从 `0xf` 变为 `0xb`，与 proposal 不再读取色度相符；这是静态取分量证据，不是显存带宽减少的测量。末级少一次 EXP 与 current 不再传播虚拟距离相符，resolve 本身的静态结果不变。

## 数值和编译验证

数学等价不保证编译后逐位一致。角色裁剪有意清零的字段按零值契约检查，其余字段才与基线比较；不能将整条原始记录都称为 bitwise 相等。`audit_post_pipeline.py` 的默认 `signal_half_ulp_tolerance` 仍为 **0**。以下完整链另行显式指定 **1 ULP**，仅允许光照矩/色度的 FP16 舍入变化，sigma、距离、几何、样本数和原始历史继续严格相等。

| 验证 | 实际结果 | 范围 |
| --- | --- | --- |
| 完整降噪链，17×9 | 37 个检查点，保留字段均逐位相等 | 时域准备、方差、两域各六级空间滤波与历史提交 |
| 完整降噪链，1920×1080 | 反射 71 的 current 在 **20 个像素、22 个半精度分量**上最多相差 **1 ULP**；此前保留字段逐位相等 | 元数据严格相等；不是全链 bitwise 通过 |
| 同一 1080p 链的最终结果 | **一个像素的色度**变化，最多 1 ULP；buffer3 的公开输出和历史重复保存，表现为 **2 条记录、4 个半精度分量**变化 | 不是两个受影响像素；buffer0/2/4 逐位相等，元数据严格相等 |
| 10 个调试视图，127×73 | 23/24/25/30/31/32/35/36/37/38 全部通过，各 37 个检查点；消费的诊断字段及保留信号逐位相等 | 均使用默认零容差；不把未消费字段当有效输出 |
| CPU 审计 | 8/8 通过，测试代码未改动 | Bures、漫反射引导、实体折射、估计量方差、MC 方差契约、反射引导、不确定性入口、方差精度 |
| 编译与 SPIR-V 验证 | **82 个入口 × 3 组配置 = 246 项**全部通过 | 默认；`EON_ENABLED=0`；关闭 EON、END_SKYBOX 和三类引导强度 |

完整链结果在 `temp/bench11/final/chain_correctness.json`，调试结果在 `debug_views.json`，CPU 记录在 `temp/bench11/cpu_audits/report.json`。三组编译记录在 `temp/pipeline_audit/bench11_final/`、`bench11_eon_off/`、`bench11_features_off/`。补充 ABI 注释后又核对了全部 82 个展开入口，去除注释与空白后的代码与已编译产物一致。

上述 1 ULP 是这组输入、设备和驱动下实际观察到的边界，不是对任意场景和跨帧误差的数学保证。它也不能作为允许修改拒绝条件、权重或持久元数据的依据。

## 最终 1080p 连续空间计时

设备为 RTX 4060 Laptop，NVIDIA 610.62。基线与当前都使用图像 scratch，一个 query 覆盖同一域连续五级或六级 dispatch 及级间屏障，输入 GPU 恢复在 query 外。每行 31 组 A/B、B/A 交替配对，全部计时结束后才读取 query 和输出；图像绑定为 `READ_WRITE`，屏障位为 `0x2028`。源码摘要、工作组、原始配对与 p10/p90 均随报告保存。

coherent 输入包含连续几何及边界，mixed 输入包含混合法线、方向和 HDR 信号；均使用非单位相机旋转、有效/无效及未知方差记录。以下毫秒是空间链测量，百分比使用配对的 `1 - 1 / median(T基线/T当前)`，不是两列独立中位数的比值。

| 输入 | 域 | 空间级数 | 基线中位数 ms | 当前中位数 ms | 配对耗时下降 |
| --- | --- | ---: | ---: | ---: | ---: |
| coherent | diffuse | 5 | 8.7204 | 7.0318 | 19.84% |
| coherent | reflection | 5 | 8.4767 | 6.7164 | 21.62% |
| mixed | diffuse | 5 | 8.8719 | 6.8628 | 23.67% |
| mixed | reflection | 5 | 8.8054 | 6.9775 | 20.90% |
| coherent | diffuse | 6 | 10.3844 | 8.4644 | 18.83% |
| coherent | reflection | 6 | 10.7715 | 8.9866 | 18.00% |
| mixed | diffuse | 6 | 10.8093 | 8.6784 | 19.32% |
| mixed | reflection | 6 | 10.8001 | 8.7255 | 18.07% |

四行五级测试中，两个估计器的消费字段都逐位相等。六级测试不能标为 bitwise；补充的 `temp/bench11/final/spatial_six_correctness.json` 已完成逐字段量化：

| 六级输入 | 每域变化记录数 | 光照矩/色度变化分量 | sigma 变化分量 | 实测变化幅度 |
| --- | ---: | ---: | ---: | --- |
| coherent | 20 | 17 | 3 | 每个变化分量均为有限 FP16，恰好 1 ULP |
| mixed | 38 | 36 | 2 | 每个变化分量均为有限 FP16，恰好 1 ULP |

两域接收相同输入，因此各自得到相同的差异位置和数值。current 的闲置虚拟距离满足角色规范化后的零值契约；sigma 的有效/未知/无效标签完全一致，但少量有效 sigma 的数值不逐位相等。原先“只允许光照舍入、元数据严格相等”的检查**拒绝了全部四个六级样本**，工具及门限没有为此放宽。这份补充记录是数值舍入诊断，不能记成该严格测试通过。

本轮保留实数公式和贡献累加顺序，编译后的 FP16 舍入仍可能不同。这些空间专用输入与前述“时域准备到历史提交”的完整生产链输入不同：后者在 1080p 的 sigma 严格相等，最终仅一个像素色度相差 1 ULP；不能将其结果延伸到所有 fixture。这里测到的 1 ULP 也只是当前样本、设备和驱动的边界，不是全输入或长期时域误差的全局保证。

原始文件为 `temp/bench11/final/chain_{coherent,mixed}_{5,6}.json`。这些配对说明本轮七模块组合在两种连续空间负载下减少了耗时；它们不包含方差准备、resolve、前帧辉光交接或游戏宿主时间，也没有隔离上轮 SSBO → 图像迁移的成本。**当前仍不能据此报告游戏整帧收益，或断言用户观察到的倒退已经解决。** 后续游戏捕获应继续使用相同画面与设置，记录绝对帧时和相关 pass/屏障，复核前文尚未闭合的因果假设。

## 存储与辉光交接的单变量对照

为进一步区分算术与存储，本轮又建立了 `temp/bench11/storage_control/shaders`。它保持最终七模块算法、字段裁剪、调试策略和末级调度逐字节一致，仅恢复原始 SSBO scratch 的 planes 8/9、访问器及对应分配。第三个方案保持当前图像算法，但用独占图像与辉光资源分开。此处三种方案都使用**当前算法**，不能代替历史版本的反事实游戏捕获。

`temp/bench11/storage_lifecycle.py` 在同一 OpenGL 上下文执行以下对照：真实辉光 90–93 → 固定输入生产器 → 漫反射前五级。生产器通过 imageStore 或 SSBO 写入相同的准备后数据，替代实际方差准备，以隔离存储路径。真实辉光着色器及其工作组保持原样；交替旋转三种方案的顺序，各测 31 组，批次结束后才读取计时及输出。

| 测量范围 | 复用图像 ms | 独占图像 ms | SSBO ms | 独占相对复用的配对耗时下降 | SSBO 相对复用的配对耗时增加 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 无辉光前置，仅空间链 | 7.3861 | 7.4045 | 8.1029 | 1.11% | 9.90% |
| 辉光和生产器之后，仅空间链 | 7.1803 | 7.2356 | 7.9606 | 0.04% | 9.37% |
| 辉光＋生产器＋空间链 | 9.2160 | 9.0061 | 9.9676 | 2.24% | 7.10% |

毫秒仍为各列中位数，百分比来自配对比值，不能用独立中位数直接复算。三种方案的两个估计器消费字段在该输入上逐位相等。以这批配对样本进行 10,000 次 bootstrap，独占图像前两行的耗时下降 95% 区间分别为 [-0.95%, 2.73%]、[-3.43%, 2.06%]；组合范围为 [0.66%, 3.80%]。这些区间只描述当前批次，并不包含跨捕获、温度及频率的不确定性。

该实验支持当前算法下的图像读取收益，也观察到组合范围中较小的复用成本；没有在空间链上重现明显的独占图像收益。专门分配两个 1080p RGBA32 图像还需约 63.3 MiB，当前保留复用方案。不能将这里约 2.2% 的组合差异唯一归因于某条屏障或格式转换，也不能由此排除游戏宿主中的跨帧成本：测试不包含实际方差、两域完整调度、帧间几何/PT 工作或窗口系统提交。

原始数据、配对区间及候选核查分别在 `temp/bench11/final/storage_lifecycle.json`、`storage_lifecycle_ci.json`、`temp/bench11/storage_control/audit.json`。这补充了前文的资源生命周期假设：当前最有实测支持的改进来自减少计算与活跃字段；存储复用的较小成本应与游戏时间线一起继续核对。
