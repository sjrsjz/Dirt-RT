# 根据 1080p GPU 捕获进行的优化

> 后续反馈：用户报告本轮修改后游戏内性能倒退，并提供 `temp/analysis_11.yaml`。本文保留上轮实现和独立微基准的历史记录；这些结果不足以证明游戏收益。新的指标对照、主次因假设与验证方法限制见[捕获 11 联合诊断](bench11_joint_optimization.md)。

本轮依据本地 `temp/analysis_10.yaml` 定位热点，修改统一降噪器的临时存储、末级输出生命周期和诊断写入。两个信号域使用相同的空间算法、工作组规则和存储格式。以下收益来自实际生产着色器的独立 GPU A/B 测试；尚未重新采集游戏内整帧性能。

## 捕获的正确读法

实际文件名是 `temp/analysis_10.yaml`，SHA-256 为 `a0bcf4aa6c49e1d65f3ca634b747e3a36fe936aef5713077969ebd8ffc2f41ae`。解析器及完整指标分别在 `tools/analyze_gpu_profile.py` 和 `temp/bench1080/profile_review/report.json`。

`composite` 的 **45.7912%** 是后续编号 composite 区间的父级汇总：子区间时间占比之和完全相等，CS/PS 线程数和 draw 数也分别相等。不能将它当作 PT 耗时，再与子区间相加。两个 `prepare` 记录完全重复，计一次。去重后的叶区间只覆盖整帧 **47.4186%**；剩余 **52.5814%** 没有足够的阶段归属信息。

## 进入生产代码的改动

### 统一临时存储复用现有图像

`lib/lighting/denoiser/scratch_io.glsl` 将独立当前估计器的 scratch A/B 从 diffuse SSBO 的第 8/9 平面迁到现有 RGBA32F `bloomAtlas` / `bloomBlur`。写入使用 `imageStore`，邻域读取使用 `texelFetch`。两个信号域依次复用同一对图像，辉光在 composite90 以后覆盖这些资源；没有新增图像、分配或调度阶段。

每个信号仍保存原来的四个 FP16 对编码字。存入浮点图像前对每个 uint 加 `0x00800000`，取出后以整数减回。有限 FP16 上半字使原 FP32 指数至多为 247，加偏置后指数落在 1–248，全部成为有限正规 FP32，避免直接 bitcast 产生的次正规数被清零。整个传输没有对负载做浮点算术；这不是重新量化信号。

`bufferObject.2` 从 160 降到 **128 bytes/allocated pixel**，八个持久平面及其编号保持不变。1080p 原生像素数对应减少 **66.3552 MB**，实际分配另有原有的 1.1×1.1 余量。详细调度见[降噪阶段表](../shaders/post/denoiser/README.md)。

### 末级只计算有消费者的输出

新模块 `atrous_policy.glsl` 根据迭代生命周期决定是否累加和写出 proposal。前五级仍传播 proposal 与独立当前估计器；第六级仍读取 proposal，完整保留邻域权重、几何拒绝和两个输入的共同有效性判断，但最终历史提交只消费独立当前估计器。

因此 composite56/71 默认省去 proposal 累加器、方差传播、编码和图像写入；composite58/72 省去对应的图像读取及不可达 fallback。两个 filtered-sigma 调试视图需要 proposal 统计时，仅保留其累加，不恢复无人读取的图像输出。

这同时消除了两个域各一次 16 字节/像素的写入和读取，1080p 合计 **132.7104 MB/帧逻辑流量**。它不是测得的显存总线字节数。独立当前结果、raw/filtered 历史、几何、样本数、引导和公开输出在 GPU 对照中保持逐位一致。

### 诊断只写当前视图消费的字段

`lib/buffers/debug_buffer.glsl` 按编译期 DEBUG_VIEW 裁掉闲置 producer。普通视图没有诊断写入；噪声权重、采样方向、sigma 和时域状态分别只在对应视图写入。sigma 的闲置半字直接置零，消除读改写依赖。

仅两个 resolve 的默认诊断写入就减少 **49.7664 MB/帧逻辑流量**。RT 方向诊断也不再无条件写入，但此捕获不足以给它分配独立 PT 提速数字。

## 1080p 配对 GPU 计时

设备为 RTX 4060 Laptop，OpenGL 驱动 610.62。基线是本轮修改前保存的完整源码 `temp/bench1080/baseline_shaders`，已经包含此前的数学与模块化工作，不能将这些增益再次计入本轮。

`tools/audit_post_pipeline.py` 编译生产 compute 入口，以混合粗糙度、方向、HDR、有效/无效及未知方差输入运行。两域空间核使用相同输入验证统一性。31 组 A/B、B/A 交替配对；空间核每次 query 执行 4 次，方差准备执行 8 次，resolve 执行一次。resolve 每次 query 前用 GPU 拷贝恢复输入历史，拷贝不计入 query。源码摘要、原始空间配对样本和 p10/p90 位于 `temp/bench1080/final/gpu_1920x1080.json`。

## 验证和未采用的候选

- 全部 **82 个着色器入口**在默认、EON 关闭、附加功能关闭三组配置下编译并通过 SPIR-V 校验；保留字扫描通过。
- 1080p 完整降噪链的所有保留中间输出和最终生产 SSBO 逐位一致。检查项包含末级死图像缺席和默认无诊断写入；两域每级独立当前输出也逐位一致。
- 10 个诊断视图（23/24/25/30/31/32/35/36/37/38）在完整链路上验证，实际消费的诊断字段与基线逐位一致。
- 图像传输穷举全部 63,488 种有限 FP16 上半字和 16 种代表性下半字，共 **1,015,808 个编码字**，CPU 和实际 GPU 双图像往返逐位一致；另有 4,096 组生产信号覆盖正负零、次正规数、极值、未知/无效 sigma 及非有限入口。
- 生产辉光 90→91→92→93 在降噪脏数据占用过图像后，与干净图像输出逐位一致；覆盖 1920×1080、257×145、17×9、3×2、1×1、1×7。
- 检查实际安装的 `iris-fabric-1.11.2+mc26.2.jar`：`CompositeRenderer` 的 compute 调度后调用 `memoryBarrier(0x2028)`，包含 shader-storage、shader-image-access 和 texture-fetch 屏障；`ComputeProgram.dispatch` 也有相同默认掩码。它覆盖本轮 imageStore→下一阶段 texelFetch 的可见性。反编译证据在 `temp/bench1080/iris_barriers.javap.txt`，不是仅依赖测试工具的全屏障假设。
- 现有八组统计、方差精度、引导及折射契约审计全部通过。此轮没有重新定义 BSDF、PDF、时域响应或估计量方差。

| 候选 | 结果 | 处理 |
| --- | --- | --- |
| 大步长统一改成 16×16 工作组 | 输出相同，耗时约为原来的 1.7–1.8 倍 | 恢复两域 8×8 |
| 大步长取消 shared 虚拟位置瓦片，直接加载四邻居 | 输出相同，耗时增加约 20%–28% | 恢复共用瓦片 |
